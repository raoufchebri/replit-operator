# Entry paths

Replit supports four related entry paths. Choose the one that matches the requested outcome, then verify the visible state before entering content or taking action.

## Conversation and artifact-guided build

Use a conversation for questions, research, analysis across available connected sources, or agent-led work. A build can start from natural-language intent alone or from an artifact choice that adds a visible request pill to the composer.

- The live New control can expose artifact choices when its navigation is expanded; if that surface is not available, use the composer Add attachment menu and Create something new submenu.
- Selecting an artifact is context-setting, not project creation. Verify the visible pill, such as Website, before prompting.
- The inspected artifact menu contains Website, Mobile, Design, Slides, Animation, Data Visualization, 3D Game, Document, Spreadsheet, and Figma attachment. This catalog is volatile.
- Remove accidental artifact context before a message is submitted. Obtain approval immediately before submitting a build request.
- A verified Free-mode conversation completed both web research and a read-only Slack/Linear analysis without asking for mode escalation. Treat this as evidence for comparable tasks, not a guarantee for all source scopes or task sizes.
- A verified website build created a project and entered Build view. The project preview can be launched from Run the app; verify its visible interface and required controls before declaring the build successful. Do not publish unless separately approved.

## Projects

Projects provides a browsable inventory of accessible work. Confirm the workspace before interpreting its contents.

- The inspected view has Search, status filtering, artifact-type filtering, a scope filter, and Grid/Table view controls.
- The status filter currently includes Any status, Any published status, Published, Failed, and Draft. Artifact types currently include Design, Web, Data, Mobile, 3D Game, and Slides. Verify these menus live.
- Searching and filtering are read-only. Opening a project, changing project scope, or editing it is a separate workflow that requires explicit user intent.

## Routines

Routines are scheduled agent tasks. Treat a routine as an external, potentially recurring action.

- The inspected Routines page is marked Beta and loads asynchronously. Wait for the routine list, active state, schedule, time zone, run budget, and routine options to render before acting.
- Opening a routine reveals its conversation and a details pane for inspecting it. Do not toggle active state, alter schedules, budgets, or integrations without approval.
- The page provides suggested routine prompts and a Schedule a routine entry point. Entering the creation conversation is discovery-only; finalizing a scheduled routine requires immediate approval after schedule, destination, recurring behavior, and cost are shown.
- Routine creation opens a confirmation card with title, message, schedule, and per-run budget. The verified interface states that routines run in Power mode. Record the final values, obtain confirmation, then verify the created routine, next-run time, and active state.
